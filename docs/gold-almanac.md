# Gold Almanac

The public state guide lives at `/gold-almanac/<state-slug>/`. `/gold-almanac/` starts with California; a GET form can select any state without JavaScript. All 50 states have independent canonical URLs. Client selection updates history only after the new dashboard is received. Hover changes a map fill, never the selected data; arrow keys move focus and Enter/Space select. The reader explicitly chooses when to scroll to details. Alaska/Hawaii have insets; small-state labels and the dropdown provide alternate targets.

## Data and editing

- `app/almanac/states.json`: US postal/FIPS identities and precompiled real state outlines. Stable ID `US-ME`, slug `maine`.
- `app/almanac/content.json`: versioned public editorial notes, facts, official references, and ten selected archival catalog leads. This is deliberately separate from presentation code. CA, ME, NC, NV, NH, VT, MA, CT, and RI have sourced first-pass guides. The New England batch includes historical/geological context and dated access notes; it is not an exhaustive inventory. Other states remain open for research. Six additional states have archival catalog leads without a claimed modern gold occurrence.
- `app/almanac/model.js`: validates source IDs, article relationships, attribution, statistic units/reporting periods/geographic scope, and review dates. Reuses `creator-catalog.json` and `publishedArticles()` directly. Creator names, biographies, and article text are not duplicated in the state dataset.
- `app/almanac/store.js`: read-only public MariaDB projection. Reuses published `regions`, `person_regions`, `resources`, `resource_regions`, `source_references`, and `channels`. Descendants of an explicitly identified US state are followed to four levels. Creator associations require sourced `covers` or `teaches_in` relationships and a public checked source; `based_in` alone is excluded. If migration 005 already exists, explicit published creator-waterway evidence is included. Draft, archived, sample, and private records remain excluded.
- Roster fallback uses only reviewed/published explicit state coverage. Broad regions are not expanded into guessed states. Known business-headquarters-only entries are excluded. Live hidden/archived records suppress roster entries. A disconnected local preview offers official channel links; internal profiles appear when the directory database is connected.
- No schema migration, new dependency, API key, map provider, AI service, or environment variable is needed. The existing `DB_*` configuration connects live public relationships. Existing database migrations remain prerequisites for their corresponding records; this feature does not publish draft research or alter rows.

Each state fact/history/place/access note has a stable record ID, source IDs, a review date and a clear status. Statistics additionally carry value, unit, period, scope, definition and locator. Newsletter editors can select those record IDs and retain the original source metadata, rather than copying an unattributed number. No newsletter publisher was added. Archival `ia:<identifier>` records are metadata-only leads with author/year/Archive URL; they are not passage-verified facts and no book text or rights assumptions are published. All external links open a new tab.

To add research, edit the JSON rather than views. Add a source with publisher, HTTPS URL, checked date and locator; then reference that ID in a claim. A rush date must not be substituted for a first documented discovery. Historical mine inventories must not be presented as active-operation counts. Add article IDs only for actual published articles and describe whether the relationship is technique reading or state-specific research. Unsupported figures stay absent and display “Not yet researched,” never zero. Locations are historical/occurrence references unless the note cites explicit official permission for the stated activity. Camp Plymouth’s Buffalo Brook entry cites the park’s hand-panning permission, with park-boundary and equipment limits; this is not permission outside that boundary. `accessNotes` contains short, sourced, dated summaries validated just like other editorial claims, with `source_checked` status required. Official guidance is dated, with no blanket permission claims.

## Runtime and validation

The existing Node server handles the HTML routes and `/api/gold-almanac/<slug>/` (public GET/HEAD only). Public database projections are cached per state for 60 seconds; outages retry after 15 seconds, retaining the independent editorial notes without exposing database diagnostics. Browser requests are abortable and sequence-checked so rapid selections cannot replace newer state data with stale responses. Failed selections retain the prior guide and offer a retry; stalled browser requests time out after 15 seconds. Browser cookies, precise locations, and private accounts are not used.

Run the existing build/check and test commands (`npm run build`, `npm test`), or the exact package scripts with Node if npm is not installed. `tests/almanac.test.js` covers geometry/50-state identities, sourced-content validation, sparse state behavior, creator coverage and blocked records, escaping, timestamp limits, SQL public-projection guards, canonical routes, all 50 APIs, cache and outage fallback. Client tests exercise race cancellation, failure/retry, sharing and Back behavior. Browser checks cover real map clicks, dropdown sync, keyboard navigation, section links, refresh, and narrow viewports.

The local preview can run with `PORT=3051 node server.js`, then visit http://localhost:3051/gold-almanac/california/ . Production uses the existing GitHub/Hostinger deployment workflow. Live MariaDB integration must be checked against Hostinger after deployment; no production database credentials were present in this local session and no production deployment was performed.
