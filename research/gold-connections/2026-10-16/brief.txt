
PROJECT: GOLD CONNECTIONS
Website: https://www.goldtrails.org

Build a fully functional, responsive community events and meetup system called "Gold Connections" within the existing Gold Trails website.

GOAL
Create a Meetup.com-style experience specifically for gold prospectors, hobbyists, and Gold Trails members.

This is a new feature of the existing website, NOT a separate website.

IMPORTANT:
- Inspect the existing codebase before making changes.
- Reuse existing authentication, database, UI components, and Stripe subscription infrastructure.
- Preserve all existing website functionality.
- Match the established Old West visual identity.
- Do not replace existing working systems.
- Build real functionality, not mockups.
- Never expose private member information.
- Do not send real notification emails during testing.

1. MEMBERSHIP AND ACCESS

Gold Connections is included with Gold Trails Plus membership at $5/month.

Public visitors can:
- Browse upcoming events.
- Search and filter events.
- View public event details.
- See state group pages.
- See event previews and public comments where appropriate.

Gold Trails Plus members can:
- Create events.
- RSVP to events.
- Comment on events.
- Subscribe to state notifications.
- Manage their own events.
- View and manage their RSVPs.
- Participate in online and in-person meetups.

Use existing Stripe subscription status to determine eligibility.

Do not create a separate Gold Connections subscription.

Display an appropriate Gold Trails Plus signup invitation when a nonmember attempts a restricted action.

2. THE 50 STATE GROUPS

Create exactly 50 permanent state groups, one for each U.S. state.

Each group includes:
- State name and abbreviation.
- State-specific event listings.
- Upcoming and past events.
- Member notification subscriptions.
- Links to the corresponding Gold Trails State Almanac page.
- Event creation button for Plus members.

State groups are organizational categories, not separate paid memberships.

Do not create 50 independent membership systems.

Users may follow multiple states.

Maintain one national event database with state associations.

5. GEOGRAPHIC NOTIFICATION SYSTEM

This is an important feature.

When creating or publishing an event, the organizer selects ONE of three notification ranges:

OPTION A:
My state only.

OPTION B:
My state plus all directly neighboring states.

OPTION C:
My state plus states up to two state-border crossings away.

Example:
An event in Massachusetts with Option B would notify subscribers in Massachusetts and directly neighboring states.

Option C expands outward another level.

IMPLEMENTATION:
- Maintain a verified adjacency table for all 50 states.
- Use state-border relationships, not mileage radius.
- Treat Alaska and Hawaii appropriately.
- Never invent geographical connections.
- Calculate notification states automatically.
- Display the selected states to the organizer before publishing.

Users can subscribe to notifications for one or more states.

For a published event, send email notifications to eligible subscribed members within the organizer's selected geographic range.

IMPORTANT:
- Send only one email per recipient per event.
- Respect email notification preferences.
- Provide unsubscribe controls.
- Do not email unsubscribed users.
- Use background jobs or queues.
- Record notification delivery status.
- Avoid duplicate sends.
- Rate-limit outbound emails.
- Follow applicable email requirements.

Allow organizers to preview notification coverage before publishing.

For clarity, use the event's host state as the center of the notification calculation.
